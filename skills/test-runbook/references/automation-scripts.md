# 脚本原语库（生成侧）

> 本文件只定义**卡片格式与复用规则**，不存放任何实际脚本、路由、选择器或账号。实际卡片与可执行用例一律落在被测项目：`docs/testing/_lib/...` 与该项目自己的 e2e 目录（如 `tests/e2e/...`）。skill 仓库出现项目脚本视为越界。

脚本档的**执行期义务**在 `references/templates/runbook.md` 的契约 R5；本文件只定：什么样的脚本能进库、卡片长什么样、复用前怎么验、什么时候作废。

## 合段断言 vs 脚本档

- **合段断言**：一段 inline 脚本覆盖连续步骤，只交 `observed`，不产出可复用资产；跑完把结果写进 runbook 证据即可。
- **脚本档**：在合段断言基础上，通道有语义定位 + 自动等待 + 脚本导出，且动作值得跨需求复用；要有卡片 + 被测项目内的可执行用例。

两者都不允许脚本宣布验收通过；判定仍由执行会话逐条比对「预期」后写。

## 能进库的与不能进库的

能进库的只有**原语**：一段有明确出入口的可重复动作，比如「登录」「打开新增任务弹窗」「按条件筛出第一行并读出某列」「填一组相容出题数据」。判据是它能被下一条旅程直接调用，不需要知道上一条旅程的验收条款。

不能进库的：

- **验收判定**。判定步必须本轮当场观测，脚本不得携带"通过/不通过"的结论。
- **写死的环境值**。入口 URL、账号、库名、端口一律从环境文档取，卡片里只留占位符与条目号引用。
- **一次性的探索脚本**。探索阶段写的临时代码不进库，先跑通、再抽成原语、再写卡。
- **绕过界面的数据操作**。用接口或 SQL 直接造出的状态，不能当作页面已实现的证据；只能作为"数据侧辅证"单独标注。

## 卡片位置与命名

```
docs/testing/_lib/<module>/<primitive>.md     # 卡片：用途、锚点、probe、失效判据
tests/e2e/<module>/<primitive>.spec.ts        # 可执行用例（项目自己的 e2e 目录）
```

模块名取被测系统的一级菜单或代码模块名；原语名用动词短语：`open-create-task-modal`、`fill-compatibility-matrix`、`read-sample-code-column`。按原语归档，不按需求归档。卡片里记可执行用例的相对路径；**两者都随被测项目走（或放项目指定的独立 e2e 工程），不放进 skill 仓库**。

## 卡片版式

```markdown
# <module>/<primitive> — <一句话做什么>

## 用途与边界
- 可用于：导航／造数／读数（读数只作为观测辅助）
- 不可用于：替判定步下结论
- 覆盖步骤类型：<例：打开弹窗 + 填三个必填项 + 提交>

## 锚点
- 路由：<path> ｜ 组件：<文件:行> ｜ 核对日期：<YYYY-MM-DD>
- 通道：<环境文档#浏览器通道 E-xx 的通道名>
- 入参来源：<环境文档#被测入口 E-xx / #测试数据 D-xx>

## 入参与出参
- 入参：<名称> — <类型，来源>
- 出参：`[{step, observed}]`，每项对应 runbook 步骤号，不含结论

## probe（复用前必须跑，3–5 条）
1. <路由可进入：URL 含 …>
2. <关键控件存在：可见文本 …>
3. <关键字面未变：标题/按钮文案逐字 …>

## 失效判据
- <任一条 probe 不成立，或组件/路由/文案与锚点不一致> → 标 `脚本失效`，回落实探，并往发现台账追加一行（类型=坑）

## 最近一次通过
<YYYY-MM-DD> ｜ 被测版本/提交 <...> ｜ 由 <R1／R2> 使用
```

## 复用流程（执行会话照做）

1. 读卡片的「锚点」，和当前代码或页面比对；对不上直接判失效，不要先跑一遍看看。
2. 跑 probe；全部成立才能用于本轮的导航/造数步骤。
3. 用于 runbook 时，脚本只返回 `observed`，判定仍按契约 R2 由执行者写。
4. 本轮结束后更新「最近一次通过」；发现失效就标 `脚本失效` 并记台账，不要静默改脚本——旧卡改没改过，下一次没人分得清。

## 分段与超时

- 单段 ≤5 步或 ≤30s，超了拆段；一段对应 runbook 里连续的一段步骤号。
- 等待用轮询条件成立，不串长 `setTimeout` 链；长嵌套会让 CDP 通道超时（`-32003/-32603`），归"坑"。
- 一段失败即停，后续步骤由 runbook 标 ⏭；不要把失败吞掉继续跑。

## 入库与淘汰

`_lib/` 是资产，应随被测项目入库（忽略规则写法见 `references/artifact-layout.md`）。同一原语只保留最新一张卡，被取代的删除并在新卡写"取代于 <日期>"；跨需求都不再用的原语直接删，不留在库里当考古材料。
