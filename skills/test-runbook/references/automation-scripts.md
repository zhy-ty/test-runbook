# 脚本原语库（生成侧）

> 本文件只定义**卡片格式、运行属性与复用规则**，不存放任何实际脚本、路由、选择器或账号。实际卡片与可执行用例一律落在被测项目：`docs/testing/_lib/...` 与该项目自己的 e2e 目录（如 `tests/e2e/...`）。skill 仓库出现项目脚本视为越界。

脚本档的**执行期义务**在 `references/templates/execution-contract.md` 的 R5/R10；本文件只定：什么样的脚本能进库、卡片长什么样、复用前怎么验、什么时候作废。

## 执行通道与档位

- **Playwright 脚本档**（默认执行通道）：一段动作值得跨需求复用，且有稳定的原语卡/用例时用。用例放被测项目 e2e 目录或项目指定的独立 e2e 工程；卡片放 `docs/testing/_lib/<module>/<primitive>.md`。
- **合段断言**：一段 inline 脚本覆盖连续步骤，只交 `observed`，不产出可复用资产；Playwright 用临时 spec/`page.evaluate`，CDP 用 `evaluate_script`。
- **CDP inline 只做执行兜底/诊断**：不沉淀为 `_lib` 资产；要复用就提升成 Playwright 用例/卡片。
- 两者都不允许脚本宣布验收通过；判定仍由执行会话逐条比对「预期」后写。

## 能进库的与不能进库的

能进库的只有**原语**：一段有明确出入口的可重复动作，比如「登录」「打开新增任务弹窗」「按条件筛出第一行并读出某列」「填一组相容出题数据」「触发导出并把文件落到指定目录」。判据是它能被下一条旅程直接调用，不需要知道上一条旅程的验收条款。

不能进库的：

- **验收判定**。判定步必须本轮当场观测，脚本不得携带"通过/不通过"的结论。
- **写死的环境值**。入口 URL、账号、库名、端口一律从环境文档取，卡片里只留占位符与条目号引用。
- **一次性的探索脚本**。探索阶段写的临时代码不进库，先跑通、再抽成原语、再写卡。
- **绕过界面的数据操作**。用接口或 SQL 直接造出的状态，不能当作页面已实现的证据；只能作为"数据侧辅证"单独标注。
- **靠重试变绿的脚本**。失败就停；不许用 `soft`/自动重试把失败吞掉。

## 卡片位置与命名

```
docs/testing/_lib/<module>/<primitive>.md     # 卡片：用途、锚点、运行属性、probe、失效判据
tests/e2e/<module>/<primitive>.spec.ts        # 可执行用例（项目自己的 e2e 目录）
```

模块名取被测系统的一级菜单或代码模块名；原语名用动词短语：`open-create-task-modal`、`fill-compatibility-matrix`、`read-sample-code-column`、`export-report-zip`。按原语归档，不按需求归档。卡片里记可执行用例的相对路径；**两者都随被测项目走（或放项目指定的独立 e2e 工程），不放进 skill 仓库**。

## 卡片版式

```markdown
# <module>/<primitive> — <一句话做什么>

## 用途与边界
- 可用于：导航／造数／读数（读数只作为观测辅助）／下载
- 不可用于：替判定步下结论
- 覆盖步骤类型：<例：打开弹窗 + 填三个必填项 + 提交>

## 运行属性
- 通道：<Playwright project 名称/路径 或 chrome_devtools；推荐 Playwright>
- Profile：<独立 profile／auth.json；不写账号密码>
- 下载目录：<证据目录下的 downloads/；无下载写"无">
- 并发：<只读/写>｜共享数据键：<...>｜可并行组：<.../串行>｜并行隔离：<独立 context/profile/下载目录／不适用>
- 浏览器占用：<独立自动化窗口／日常 Chrome（不得同时操作）>

## 锚点
- 路由：<path> ｜ 组件：<文件:行> ｜ 核对日期：<YYYY-MM-DD>
- 入参来源：<环境文档#被测入口 E-xx / #测试数据 D-xx>

## 入参与出参
- 入参：<名称> — <类型，来源>
- 出参：`[{step, observed}]`，每项对应 runbook 步骤号，不含结论
- 下载类出参：<文件绝对路径、大小、hash；页面提示只作辅证>

## probe（复用前必须跑，3–5 条）
1. <路由可进入：URL 含 …>
2. <关键控件存在：可见文本 …>
3. <关键字面未变：标题/按钮文案逐字 …>
4. <下载目录可写；下载事件能触发（下载类）>

## 失效判据
- <任一条 probe 不成立，或组件/路由/文案与锚点不一致> → 标 `脚本失效`，回落实探，并往发现台账追加一行（类型=坑）
- <下载类：文件名/保存路径/触发控件变更 → 同样判失效>

## 最近一次通过
<YYYY-MM-DD> ｜ 被测版本/提交 <...> ｜ 由 <R1／R2> 使用
```

## 复用流程（执行会话照做）

1. 读卡片的「锚点」和「运行属性」，和当前代码/页面/通道比对；对不上直接判失效，不要先跑一遍看看。
2. 跑 probe；全部成立才能用于本轮的导航/造数/下载步骤。
3. 用于 runbook 时，脚本只返回 `observed`，判定仍按契约 R2 由执行者写。
4. 本轮结束后更新「最近一次通过」；发现失效就标 `脚本失效` 并记台账，不要静默改脚本——旧卡改没改过，下一次没人分得清。
5. 并发前确认卡片的运行属性：只读 + 无共享数据键 + 独立 context/profile/下载目录才可并行；否则串行。

## 分段、预算与超时

- 单段 ≤5 步或 ≤30s，超了拆段；一段对应 runbook 里连续的一段步骤号。
- 等待用轮询条件成立，不串长 `setTimeout` 链；长嵌套会让 CDP 通道超时（`-32003/-32603`），归"坑"。
- 一段失败即停，后续步骤由 runbook 标 ⏭；不要把失败吞掉继续跑。
- **同一动作最多 2 次（含复现）**；每份产物导出/下载最多 2 次；连续 2 次同类失败即停；诊断 ≤5 次工具调用/≤30s。
- 重试必须换一个变量（新 tab/context、重设下载行为、重新快照、换定位器、reload）；原样重复不算重试。
- dev-smoke 每份 runbook 工具调用 ≤20 次/墙钟 ≤15 min；full ≤40 次/45 min。runbook 可收紧，不能放宽超过默认的 2 倍。

## 下载原语

- 一次点击 = 一个文件：先注册 `waitForEvent('download')` 再点击，`download.saveAs(<证据目录>)`；检查 `download.failure()`。
- 一次点击 = 多个文件：用 `page.on('download')` 收集，等到文件数或业务条件满足；不要用固定 sleep 猜。
- 同机产物优先直读服务端/生成目录；只有"下载行为"本身是验收项时才让浏览器走一遍。
- 每份产物最多 2 次；失败先看 `download.failure()` 和目录，不反复点导出。
- 企业下载策略/宿主"允许自动化"弹窗记环境限制，不绕过、不写进测试步骤。

## 入库与淘汰

`_lib/` 是资产，应随被测项目入库（忽略规则写法见 `references/artifact-layout.md`）。同一原语只保留最新一张卡，被取代的删除并在新卡写"取代于 <日期>"；跨需求都不再用的原语直接删，不留在库里当考古材料。
