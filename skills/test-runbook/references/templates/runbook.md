# Runbook 模板（执行期义务在 execution-contract.md）

一份 runbook = 一条用户旅程。本文件只定义版式与填法；执行期义务、取证规则、重试/预算/并发硬规则在 `references/templates/execution-contract.md`。生成时每个 topic 实例化一份 `execution-contract.md`，runbook 只引用它的绝对路径，不再把契约正文抄进每份文档。

## 实例化规则

1. 所有 `<...>` 占位符换成本旅程的实际值。填不出就是显式缺口：写进环境文档缺口表并按 `needs-input` 处理，不许留空，也不许凭默认答案填。**不允许出现 skill 安装目录的路径**；允许出现的绝对路径只有五类：环境文档、需求快照、`execution-contract.md`、证据目录、被测项目内的脚本原语卡/可执行用例。
2. **每个 topic 只生成一份 `execution-contract.md`**，从 `references/templates/execution-contract.md` 实例化一次；每份 runbook 头部写它的绝对路径。执行会话开工先读环境文档、需求快照、契约、本 runbook；契约里的 R1–R10 对全部 runbook 生效，runbook 头部的旅程值更具体。
3. 步骤号在本文件内唯一，`R<n>#<步骤号>` 是 close-out、覆盖对照、变体分岔点、脚本段共用的引用格式。
4. 每份 runbook 只写一条旅程的终态；跨页面可以合并成同一份，终态不同才另开一份。
5. 「结果」列由执行会话当场写回，生成时留 `☐`。
6. 口令、token、真实客户数据一律**不进 runbook**，只写"见环境文档#凭据 <条目号>"这类出处；步骤里需要的死值若是敏感数据，先按写入规则落进环境文档，runbook 引用条目号。
7. 测试档、轮次、执行档、执行/诊断通道、预算、并发属性、人工介入点在头部写死。dev-smoke 的「变体」表仍保留步骤（供 full 复用），但整段标 `本轮未开启`；本轮为实探时「脚本段」表只留一行关闭原因。
8. **实际脚本与卡片一律落在被测项目**：卡片 `docs/testing/_lib/<module>/<primitive>.md`，可执行用例放该项目自己的 e2e 目录（如 `tests/e2e/<module>/<primitive>.spec.ts`）；如果项目用独立 e2e 工程，登记它的绝对路径，仍按项目资产管理。本 skill 仓库只带卡片格式与复用规则，不存放任何项目路由、选择器、账号或脚本正文。

- 执行契约：<execution-contract.md 绝对路径>（开工先读；R1–R10 + 取证规则）

## 写步骤的两条门

- **死值或取法**：每个输入值要么是写死的值，要么写清怎么取到一个满足条件的值（"输入一个已存在的手机号"不算取法，要写成"在列表第一行取该记录的手机号并记为 `M`"）。敏感值按模板规则引用环境文档条目号。
- **观测点填得出来**：预期要写成能与观测逐字比对的形式（文案、URL、状态值、条数、表头数组）。填不出观测点的那一步说明定位没做够——回到步骤 2 补查，仍无结果就记成显式缺口并问用户，不许写成"检查功能正常"。预期列也不许写"可能为空／不判失败"这类免责句；需求没规定或用户拍板的差异，移到「需求外观察」或「变体」并注明来源。

## 冷启动自检（每份 runbook 写完就做）

判据是"一个全新会话只凭 index + 环境文档 + `execution-contract.md` + 这一份 runbook，不问人能跑完并逐步判定"。通读全文，凡出现的名称（页面、按钮、字段、账号、数据、目录、通道）要么在环境文档有出处、要么在本 runbook 内有取法、要么是执行会话当场观测得到的；契约与正文里不许残留 `<占位符>`；`execution-contract.md`、环境文档、需求快照、证据目录的绝对路径逐条确认真实存在；**不出现 skill 安装目录的路径**（证据目录与脚本卡都在被测项目内）。dev-smoke 还要检查：通过步没有单步证据文件要求，失败步的 `snap-R<n>-<步骤号>.md` 命名一致，`results.md` 路径可写。出现任一需要新会话"猜"的地方，就地改成步骤。

## 完成判据

- 每份 runbook 通过冷启动自检；每步的「动作／观测点／预期／取证」四列填到位且预期可判定（「结果」列留 `☐` 给执行会话）。
- 测试档、轮次、执行档、执行/诊断通道、预算、并发属性、并行隔离、浏览器占用、人工介入点、判定步、契约路径已填；dev-smoke 的变体已标 `本轮未开启`。
- `execution-contract.md` 已由模板实例化到 topic 目录，路径可读；runbook 没有内联契约正文。
- 判定步清单与取证列一致：dev-smoke 通过步只指向 `results.md#<步骤号>`，失败步命名可预测；full 按契约分级。
- 变体段落各带分岔步骤号与本轮是否开启；文档头部基线（需求快照路径＋日期）、轮次、通道、执行档已填。
