# Runbook 模板（执行期义务的唯一语义源）

一份 runbook = 一条用户旅程。本文件定义版式、各列填法、取证规则与执行契约正文；语义只在这里写一次。实例化时照抄正文、替换占位符，**不改写规则**；index、环境文档、需求快照里都不再抄一份义务。

## 实例化规则

1. 所有 `<...>` 占位符换成本旅程的实际值。填不出就是显式缺口：写进环境文档缺口表并按 `needs-input` 处理，不许留空，也不许凭默认答案填。
   全文**不允许出现 skill 安装目录的路径**——执行会话不加载本 skill，指向安装目录就是悬空引用。允许出现的绝对路径只有三类：环境文档与需求快照（本来就要引用）、证据目录（`runbooks/evidence/R<n>-<日期>/`）、脚本原语卡（`docs/testing/_lib/...`）。取证规则已经内联在本文档里。
2. 执行契约正文与「取证规则」段随每份 runbook 一起内联（契约在头部，取证规则跟在步骤与脚本段之后）。执行会话未必加载本 skill，指向它读不到的地方比重复更糟；宁可重复正文，也不留悬空引用。
3. 步骤号在本文件内唯一，`R<n>#<步骤号>` 是 close-out、覆盖对照、变体分岔点、脚本段共用的引用格式。
4. 每份 runbook 只写一条旅程的终态；跨页面可以合并成同一份，终态不同才另开一份。
5. 「结果」列由执行会话当场写回，生成时留 `☐`。
6. 口令、token、真实客户数据一律**不进 runbook**，只写"见环境文档#凭据 <条目号>"这类出处；步骤里需要的死值若是敏感数据，先按写入规则落进环境文档，runbook 引用条目号。
7. 轮次与脚本档在头部写死：冒烟轮「变体」表仍保留步骤（供全量复用），但加一行"本轮未开启"说明；脚本档关闭时「脚本段」表只留一行关闭原因。

## 版式

```markdown
# R<n> <旅程一句话：从哪儿进、做成什么> — <topic>

> 含内部入口与凭据引用的过程产物，勿提交；要入库由用户拍板。

## 本旅程速览
- 本轮轮次：<冒烟／全量>
- 终态判据：<页面或数据上可观测到的事实，一条>
- 入口：<URL 或"从 X 菜单进入 Y">（出处：环境文档#被测入口 <条目号>）
- 定位三态：<代码确认（附文件:行）／实探观察／用户口述>；诊断上限：<能读到代码则到根因／读不到则只到现象层>
- 通道：<通道名>（环境文档#浏览器通道 <条目号>）；脚本档：<开（S1–Sk）／关>
- 前置数据：<必须已存在什么；怎么造或怎么找；要造数时写备份条目号 D-xx>
- 基线：需求快照 <绝对路径> @<日期> ｜ 本 runbook 最后核对于 <日期>

## 步骤
| # | 动作 | 观测点 | 预期 | 取证 | 脚本段 | 结果 |
|---|------|--------|------|------|--------|------|
| 1 | 打开 <URL>（环境文档#被测入口 <条目号>） | 页面标题区文案 | 出现"…"，且 URL 以 <路径> 结尾 | snap-R<n>-01 | S1 | ☐ |
| 2 | 在「<字段名>」输入 <死值，或写明取法：在列表第一行取该客户的手机号，记为 M> | 同字段回显 + 下方提示区 | 提示"…"，无红色报错 | snap-R<n>-02 | S1 | ☐ |
| 3 | 点「保存」 | 顶部 toast | 文案逐字="保存成功"，且列表首行=刚提交的值 | snap-R<n>-03 | — | ☐ |

（每步都要能被一个不认识这个系统的会话照做：动作里带具体控件名与所在页面，预期里带可比对的具体值。判定步的「脚本段」可以留空，但必须是 `—` 或段号，不许空着。）

## 脚本段

| 段 | 覆盖步骤 | 原语卡（绝对路径） | 段内断言（入口 → 出口） | 失效判据 |
|----|----------|--------------------|--------------------------|----------|
| S1 | #1–#2 | <docs/testing/_lib/<module>/<primitive>.md> | 进入：已登录且 URL 含 <路径>；退出：「<弹窗标题>」可见 | 路由、标题文案或控件名变更 → 回落实探并记台账 |

脚本档关闭时写：`本轮关闭（原因：<无前端源码／预期无法落渲染层断言>）`。

## 取证规则（执行会话读这一段，不需要读 skill 安装目录）

- **判定步与失败步**：一条命名证据，文件至少含「步骤号｜观测点｜观测值（逐字）｜与预期的差异或无」；需要页面结构时附快照段落或 aria 片段。`snap-R<n>-<步骤号>.md`。
- **其余步骤**：同一段内合并成一个 run 文件，每步一行观测值，不逐 step 开文件。`snap-R<n>-<起>-<止>.md`。
- **截图**只作辅证，不能替代读到的文字；颜色、排版、图表形状这类才必须 `snap-R<n>-<步骤号>.png`。
- **判"没出现"之前**先按该步的预期动作等一次并记下等待时长，再重试同一观测；两次都无才标 ✗，偶发成功走契约 R4a。
- **常见坑**：新开标签页先切换再操作；iframe 内控件先切 frame；原生 alert/confirm 走对话框处理，页面内自绘弹框按普通控件点；虚拟列表只渲染可见行，先滚到视口再取；校验文案区分字段下方红字／toast／按钮禁用态三种观测点；登录态掉线按环境文档#凭据重登并记台账。
- **目录**：<证据目录绝对路径>；同一条 runbook 反复跑按日期分子目录，旧证据不覆盖——回归要靠前后对比判定修复是否生效。

## 变体
| 变体 | 分岔自 | 差异步骤 | 预期 | 本轮 | 结果 |
|------|--------|----------|------|------|------|
| <非法输入／边界值／异常路径> | R<n>#<步骤号> | <差异步骤> | <可判定预期> | <开启／未开启（原因）> | ☐ |

## 未覆盖与假设
- <本旅程没覆盖的验收条款、带缺口的步骤，各注明环境文档缺口表条目号>
```

## 执行契约正文（原样实例化后放在 runbook 头部）

```
## Execution Contract — <topic> / R<n>

本 runbook 是执行会话唯一的交接入口；执行会话不加载任何编排 skill，以下义务对本旅程全程有效，与你的默认习惯冲突时以本节为准。

R1 开工前必读：环境文档 <绝对路径>（被测入口、测试数据与备份、代码库清单、浏览器通道、凭据）与需求快照 <绝对路径> 的对应条款（<条款号清单>）。
   文件里已记录的事实自己读取或按记录的探测命令实测，不得转成用户问题。
   本轮通道以环境文档#浏览器通道 <条目号> 为准；不按当轮环境临时换通道，通道不可用时停下报用户。
R2 逐步判定：只有当场观测到的事实与「预期」一致，才在该步「结果」列写 ✅ 并当场写回本文件。
   不一致 → 按 R4 停下。观测不到、或要靠"看起来正常"才算过的 → 写 `观测缺失` 并同样走 R4。
   没跑到的步骤标 ⏭，不空着。本轮轮次为 <冒烟／全量>：冒烟的「变体」整段标 `本轮未开启`，不计入完成度。
R3 取证分级：按本文件「取证规则」段执行——判定步与失败步全量、其余步骤合并成段内证据。
   没有证据的步骤不算跑过。
R4 失败分叉：停在该步，其后所有步骤标 ⏭（它们的结论不可信），然后按序做完——
   a. 先原地复现一次该步以排除偶发（同样的动作、同样的观测点）；仍失败才继续 b，偶发成功则在该步标 `偶发` 并继续旅程。
   b. 判代码可得性：读环境文档#代码库清单。路径存在且可读 → 检索到文件:方法级，写出根因假设与支撑证据；
      不可得 → 只写到现象层（复现步骤 + 观测事实 + 与预期的差异），在 close-out 标 `无码可查` 并停下向用户报告，不许编造代码级原因。
   c. 定位结论先报用户，得到同意才改代码；改完回归 **失败步 + 该验收条款的其余判定步**。
      全流程回归只在轮次=全量、或用户明确要求时执行，并把改动清单与回归结果写进 close-out。
   d. 无论是否修复，当场往发现台账 <绝对路径> 追加一行（序号按现有最大号递增，类型填 坑／环境事实／决策）。
R5 脚本档（本轮：<开／关>）：开了才适用，且只交观测不交结论——
   脚本返回 <步骤号, observed>，判定由你逐条比对「预期」后写；脚本自己宣布通过不算数。
   断言只读渲染层（可见 DOM／aria／toast／URL／控件禁用态），不许读接口响应或前端 store 代替界面观测。
   单段 ≤5 步或 ≤30s；超时拆段——长嵌套等待会把 CDP 打到超时，属工具链现象，不是被测缺陷。
   任一步 observed 与预期不符 → 立即停在该步并按 R4 走，后续步骤标 ⏭。
   复用原语卡前先跑它的失效判据（probe）：probe 不过标 `脚本失效`、回落实探、按 R4d 记台账；
   判定步不得引用历史脚本结果，必须本轮当场观测。
R6 实测证伪了环境文档已记的某条事实时，就地增量改那一条（注记里留下原值）并按 R4d 追加台账；除此之外不得重写或复制该文件。
   发现需求本身有遗漏或与页面冲突，写进 close-out 的「需回写需求快照」行，不自行改需求。
R7 造数先备份后处置：任何新增/修改数据的步骤，先按环境文档#测试数据 <条目号> 把当前状态备份到 <证据目录>/data-backup/
   （以造数主键为根，关联表一起导出）。旅程结束按该条目的「处置方式」二选一当场做完：
   后续还要同类数据且重造成本高 → 用备份回滚；否则直接删除，不把清理语句留作交付物。
   删除或回滚超出环境文档授权范围时先问用户；close-out 只记造了什么、备份在哪、怎么处置的。
R8 收尾写 close-out：<runbook 同目录>/close-out/R<n>-<YYYY-MM-DD>.md，必含——
   步骤完成度 x/y（含 ✅／✗／偶发／观测缺失／⏭ 各计数；本轮未开启的变体不计入）、每条 ✗ 的现象与证据路径、
   代码定位结论 或 `无码可查`、改动清单（无则写"无"）、回归范围与结果、数据处置（造了什么／备份路径／回滚还是删除）、
   「本 runbook 的新事实或显式缺口：无」或清单（每条带台账序号 `L-xxx`）、「需回写需求快照：无」或清单。
   "无／不确定／blocked"都是合法值：不许为好看编内容，也不许为了填满清单编造发现。
R9 交代回程：本旅程跑完（或卡住）后向用户交代最后一件事——回到生成这份 runbook 的会话（编排会话）说
   "R<n> 跑完了，请读 <close-out 绝对路径> 收尾"，或直接把你这段输出粘回去。编排会话不会自己看见你的工作目录变化。
```

（变体的切分与合并规则、轮次定义在 `SKILL.md` 步骤 3；脚本原语卡格式在 `references/automation-scripts.md`。本模板只给分岔点的列序与执行期义务。）
