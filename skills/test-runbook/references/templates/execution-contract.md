## R1 开工必读

先读环境文档、需求快照的对应条款、本契约和本次 runbook。文件里已记录的事实自己读取或按记录的探测命令实测，不得转成用户问题。执行通道以 runbook 头部为准；通道不可用时停下报用户，不按当轮环境临时换执行通道。

## R2 逐步判定

只有当场观测到的事实与「预期」逐字或结构化一致，才在该步「结果」列写 ✅ 并当场写回 runbook。只有代码确认、没有当场观测的，不得写 ✅；在 close-out 记 `代码确认` 并说明未实测。不一致 → 按 R4 停下。观测不到、或要靠"看起来正常"才算过的 → 写 `观测缺失` 并同样走 R4。没跑到的步骤标 ⏭，不空着。本轮轮次以本 runbook 头部为准：冒烟的「变体」整段标 `本轮未开启`，不计入完成度；全量才加变体和全流程回归。

## R3 取证

- **dev-smoke**：通过步的 observed 写进本 runbook 证据目录下的 `results.md`，一行一步；失败步另开 `snap-R<n>-<步骤号>.md`；视觉项加 `snap-R<n>-<步骤号>.png`。不逐 step 开文件，不为通过步单独截图。
- **full**：判定步与失败步全量、其余步骤合并成段内证据；非判定步不得单独开文件。
- 一条证据要能独立回答"这一步看到的值是什么、和预期差在哪"，不依赖对话上下文。`results.md` 的 observed 也必须是具体值（文案、URL、条数、状态、表头数组），不能写"正常"。
- 配比检查：dev-smoke 的证据文件数 = 失败步数 + 视觉项数；full = 判定步数 + 失败步数 + 合并段数。超配就是取证过量，close-out 记一行。
- 没有证据的步骤不算跑过。证据清单写进 close-out。

**`results.md` 版式（dev-smoke）：**

```markdown
# R<n> 执行结果 — <日期>
- 测试档：dev-smoke ｜ 轮次：冒烟 ｜ 执行通道：<...> ｜ 诊断通道：<...>
- 完成度：4/5

| # | 结果 | observed（逐字/结构化） | 证据 |
|---|------|--------------------------|------|
| 1 | ✅ | 标题="…"；URL 以 `…` 结尾 | results.md#1 |
| 5 | ✗ | 表头仍含 "评价结果"；首行值=不通过 | snap-R5-05.md + snap-R5-05.png |
```

**失败步 `snap-R<n>-<步骤号>.md` 必含：** 步骤号｜动作｜观测点｜观测值（逐字）｜与预期的差异｜原地复现结果｜代码定位或 `无码可查`｜诊断补充。视觉项才加同名 png。

## R4 失败分叉与试错上限

a. 先原地复现一次该步以排除偶发（同样的动作、同样的观测点）；仍失败才继续 b，偶发成功则在该步标 `偶发` 并继续旅程。
b. **硬上限**：同一动作最多 2 次（含这次复现）；每份产物导出/下载最多 2 次；连续 2 次同类失败即停。超限记 `blocked` 或 `观测缺失`，不再试。重试必须换一个变量：新 tab/新 context、重设下载行为、重新快照、换定位器、reload；原样重复不算重试。
c. **诊断**：先看执行通道自己的 error/trace/screenshot；只有 trace 解释不了时才开 CDP 诊断。诊断只读、≤5 次工具调用/≤30s、不改判定、不写 ✅；诊断结论写 close-out 的「诊断补充」行。诊断不是换执行通道。
d. 判代码可得性：读环境文档#代码库清单。路径存在且可读 → 检索到文件:方法级，写出根因假设与支撑证据；不可得 → 只写到现象层（复现步骤 + 观测事实 + 与预期的差异），在 close-out 标 `无码可查` 并停下向用户报告，不许编造代码级原因。
e. 定位结论先报用户，得到同意才改代码；改完回归失败步 + 该验收条款的其余判定步。全流程回归只在轮次=全量、或用户明确要求时执行。需求外观察经用户要求修复时，同样只回归受影响步骤；未回归前相关条款不得标 ✅。
f. 无论是否修复，当场往发现台账追加一行（序号按现有最大号递增，类型填 坑／环境事实／决策）。dev-smoke 只记会改变以后做法的条目，不写流水账。

## R5 执行通道与执行档

- 执行通道以 runbook 头部为准；本 topic 默认 <默认执行通道>。执行期不换执行通道。诊断通道只做失败步诊断，不能产出 ✅，也不能替代执行证据。
- **Playwright 执行**：脚本只返回 `{step, observed}`，判定由你逐条比对「预期」后写；脚本自己宣布通过不算数。断言只读渲染层（可见 DOM／aria／toast／URL／控件禁用态），不许读接口响应或前端 store 代替界面观测。单段 ≤5 步或 ≤30s；失败即停，不靠重试或 `soft` 把整条 spec 变绿。
- **CDP 执行**（仅无 Playwright 时兜底）：串行；用户不得在自动化期间操作同一浏览器；宿主"允许自动化浏览器"弹窗记环境限制，不绕过；下载按 R4b 上限。
- **下载**：优先 Playwright 的 `waitForEvent('download')` + `saveAs()`；同机产物直接读服务端生成的文件；只有"下载行为"本身是验收项时才让浏览器走一遍下载。CDP 兜底用 `Browser.setDownloadBehavior=allow`，但按 tab 生效，不保证后续下载；每份产物最多 2 次。企业在 `chrome://policy` 里限制下载时，记环境限制，不反复试。
- **用户共存**：runbook 头部写明是独立自动化窗口还是日常 Chrome。独立窗口时用户可用自己的浏览器，但不要操作自动化窗口；日常 Chrome 时用户不得同时操作。需要人工介入（验证码/SSO/目视）时，按 runbook 的「人工介入点」暂停并交接。
- 复用原语卡前先跑它的失效判据（probe）：probe 不过标 `脚本失效`、回落实探、按 R4f 记台账；判定步不得引用历史脚本结果，必须本轮当场观测。

## R6 环境事实增量

实测证伪了环境文档已记的某条事实时，就地增量改那一条（注记里留下原值）并按 R4f 追加台账；除此之外不得重写或复制该文件。发现需求本身有遗漏或与页面冲突，写进 close-out 的「需回写需求快照」行或「需求外观察」行，不自行改需求。

## R7 造数先备份后处置

任何新增/修改数据的步骤，先按环境文档#测试数据把当前状态备份到本 runbook 证据目录的 `data-backup/`（以造数主键为根，关联表一起导出）。会生成/覆盖文件的动作，同时按环境文档「文件副作用」列备份或取得用户显式豁免。旅程结束按该条目的「处置方式」二选一当场做完：后续还要同类数据且重造成本高 → 用备份回滚；否则直接删除，不把清理语句留作交付物。删除或回滚超出环境文档授权范围时先问用户；close-out 只记造了什么、备份在哪、怎么处置的。

## R8 close-out 与用户输出

写一份 **≤1 页** 的 close-out，版式如下，必含：完成度计数、每条失败项的现象/预期/证据、代码定位或 `无码可查`、数据处置、需求外观察、需回写需求快照、预算使用、回程路径。`无／不确定／blocked` 都是合法值，不许为好看编内容。

```markdown
# R<n> close-out — <日期>

- 测试档/轮次/执行档：<...> ｜ 执行通道/诊断通道：<...>
- 完成度：x/y（✅ a／✗ b／偶发 c／观测缺失 d／⏭ e）
- 失败项：
  | 步骤 | 现象 | 预期 | 证据 | 根因/无码可查 |
- 诊断补充：<失败步的 CDP/trace 诊断结论；无则写"无">
- 数据处置：造了什么｜备份路径｜回滚/删除｜文件副作用
- 需求外观察：条目号｜现象｜是否需求内｜用户决定｜处置状态
- 需回写需求快照：无／清单
- 预算使用：工具调用 x/y｜墙钟 x/y min｜导出 x 次｜重试 x 次｜诊断 x 次
- 证据清单：dev-smoke → results.md + 失败步 snap；full → 判定步/失败步快照 + 合并段
- 回程：回到编排会话说 `R<n> 跑完了，请读 <close-out 绝对路径> 收尾`
```

**用户可见结论只在会话末尾输出**：结果、失败步、现象 vs 预期、证据路径、数据处置。不得另建测试报告/缺陷报告；close-out 是给编排会话的机器回程件，不是用户报告。

## R9 回程

本旅程跑完（或卡住）后向用户交代最后一件事：回到生成这份 runbook 的会话说 `R<n> 跑完了，请读 <close-out 绝对路径> 收尾`，或直接把你这段输出粘回去。编排会话不会自己看见你的工作目录变化。

## R10 预算与并发

- 预算以 runbook 头部为准；默认 dev-smoke 工具调用 ≤20 次/墙钟 ≤15 min，full ≤40 次/45 min。runbook 可收紧，不能放宽超过默认的 2 倍。
- 同一动作 ≤2 次（含复现）；每份产物导出/下载 ≤2 次；连续 2 次同类失败即停；诊断 ≤5 次/30s。
- 默认串行。只有 runbook 头部同时标"只读 + 无共享数据键 + 独立 context/profile/下载目录"才可并行；写操作或共享数据键的 runbook 一律串行。
- 并发时每个 runbook 用自己的 browser context（或独立 Playwright 进程/独立 `userDataDir`）和独立下载目录；不得共用同一个 tab 或同一个下载目录。

## 取证规则

- **先等再判**：判"没出现"之前，按该步动作等一次并记等待时长，再重试同一观测；两次都无才标 ✗。偶发成功走 R4a。
- **读文字优先**：文案、URL、条数、状态值、表头数组是判据；截图只作辅证，除非该步预期本身就是视觉属性。
- **只读渲染层**：可见 DOM/aria/toast/URL/控件禁用态。禁止用接口响应、前端 store、localStorage 代替界面观测。
- **常见坑**：新开标签页先切换再操作；iframe 内控件先切 frame；原生 alert/confirm 走对话框处理，页面内自绘弹框按普通控件点；虚拟列表只渲染可见行，先滚到视口再取；校验文案区分字段下方红字／toast／按钮禁用态；登录态掉线按环境文档#凭据重登并记台账；下载类先看文件系统，页面提示只作辅证。
- **目录**：<证据根目录>；同一条 runbook 反复跑按日期分子目录，旧证据不覆盖——回归要靠前后对比判定修复是否生效。
