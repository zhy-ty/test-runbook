# 产物布局与版式

版式在这里，运行时语义在 `SKILL.md` 对应步骤里，各写一次。执行期义务在 `references/templates/execution-contract.md`，本文件不抄。

## 目录布局

```
docs/testing/
  YYYY-MM-DD-<topic>/
    index.md                        # 续接索引：路径、测试档、通道、并发分组、覆盖对照、旅程状态
    environment.md                  # 环境事实唯一源（入口、数据、代码、凭据、通道角色、预检、缺口）
    requirement.md                  # 需求快照：dev-smoke 只留验收相关摘录；full 留全文
    execution-contract.md           # 本 topic 唯一的执行契约 + 取证规则（从模板实例化）
    discoveries.md                  # 发现台账：只记会改变以后做法的条目
    runbooks/R1-<slug>.md           # 一份 = 一条用户旅程，头部引用 execution-contract.md
    runbooks/close-out/R1-<YYYY-MM-DD>.md   # ≤1 页的机器回程件
    runbooks/evidence/R1-<YYYY-MM-DD>/
      results.md                    # dev-smoke：通过步的 observed 一行一步
      snap-R1-<步骤号>.md           # 失败步证据（dev-smoke 只在失败时生成）
      snap-R1-<步骤号>.png          # 视觉项的辅证
      data-backup/                  # 造数前的当前状态备份（有造数才建）
  _lib/                             # 脚本原语库（资产，跨需求复用）
    <module>/<primitive>.md
```

**两类文件的提交口径不同：**

- `YYYY-MM-DD-<topic>/` 下的是**过程产物**：默认不进提交清单（环境文档常含地址与凭据，execution-contract 含绝对路径），把 `docs/testing/*` 加进被测项目 `.gitignore` 是默认做法。
- `_lib/` 下的是**资产**：应该入库。在被测项目里需要给忽略规则开个口子，注意不能只写 `!docs/testing/_lib/`——父目录被排除时反选不生效，正确写法是：

```
docs/testing/*
!docs/testing/_lib/
```

跨需求都要用到的结论仍要落进 ADR、词汇表或被测系统自己的用例库，不能只活在过程文档里。

## 测试档：dev-smoke vs full

| 产物/行为 | dev-smoke（默认） | full（显式开启） |
|---|---|---|
| 轮次与变体 | 冒烟；变体整段 `本轮未开启` | 冒烟或全量；变体按需开启 |
| 旅程步数 | 3–8 步，只写主流程；超过 10 步拆旅程或切 full | 按旅程完整展开 |
| 取证 | 通过步写 `results.md` 一行；失败步才开 `snap-*`；视觉项加 png | 判定步与失败步全量，其余合并 |
| close-out | ≤1 页，只留机器字段 | 可展开，但仍不写用户报告 |
| 需求快照 | 验收相关摘录 + 条款清单 | 原文落盘 |
| 发现台账 | 只记会改变以后做法的条目 | 可记完整台账 |
| 用户报告 | **不生成**；bug 在会话末尾说 | **不生成**；bug 在会话末尾说 |

默认 dev-smoke。用户明确说"全量/完整回归/按专业测试来"时才切 full，并写进 index 与 runbook 头部。

## environment.md（环境文档）

规则语义见 `SKILL.md` 步骤 0；本文件给表头与填法。条目号 `E-`／`D-`／`C-` 写入时递增，只用于引用，增删行不挪号——runbook 里所有"见环境文档#被测入口 E-02"都靠它落点。

```markdown
> 含内部地址与凭据引用的过程产物，勿提交。

- 测试档：<dev-smoke／full> ｜ 本轮轮次：<冒烟／全量>
- 执行方式：<用户开新会话>／<自检轮（不构成交付验证）>

## 被测入口
| 编号 | 名称 | URL 或菜单路径 | 所需登录态/角色 | 当前状态 | 探测方式 |

## 测试数据
| 编号 | 需要什么数据 | 怎么造（页面/接口/SQL） | 怎么找（页面筛条件或代码位置） | 当前是否存在 | 备份快照 | 处置方式 | 文件副作用 |

## 代码库清单
| 仓库 | 绝对路径 | 角色（前端/后端/共享库/e2e 工程） | 备注（版本基线、未提交改动） |

## 凭据（按来源）
| 编号 | 用途 | 来源类型（配置文件/用户口头给出/无来源） | 路径+键名 或 原样值 | 权限范围 |

## 浏览器通道
| 编号 | 通道（MCP／本地工程） | 角色（需求读取/执行/诊断） | 本机可用 | 能力（语义定位/自动等待/脚本执行/脚本导出/下载） | 验证方式与结果 | 登录态/Profile | 下载目录 | 本轮结论 |
|------|----------------------|--------------------------|----------|--------------------------------------------------|----------------|----------------|----------|----------|

## 浏览器预检
| 检查 | 结果 | 影响 |
|------|------|------|
| 下载目录可写 | | |
| 自动下载/多下载权限 | | |
| 企业下载策略（chrome://policy） | | |
| 宿主“允许自动化浏览器”弹窗 | | |
| PDF/Office 查看能力 | | |

## 显式缺口
| 缺什么 | 最迟复核时点 | 影响哪些 runbook | 是否阻塞本轮测试 |
```

「当前是否存在」「当前状态」按实测填并附探测时间。**代码库清单为空或路径不存在 → 本轮所有 runbook 的诊断上限记为现象级**，这个结论同时写进 index。"怎么找"填的是当场能执行的动作（在哪个页面按什么条件筛出第一行），填不出来就是 runbook 里 `观测缺失` 的源头，优先在这里补而不是在执行会话里问人。

「备份快照」与「处置方式」只对需要造数的行必填：备份以造数主键为根、关联表一起导出，落 `data-backup/`；处置方式写 `回滚`（后续还要同类数据且重造成本高）或 `删除`（不需要或重造成本低）。两列都不能留给执行会话现场决定。

「文件副作用」写审核、导出、上传等动作会生成或覆盖的文件：路径、是否备份、还是用户已显式豁免。只回滚数据库、不处理文件，会把环境留在半回滚状态；没有文件副作用就写 `无`。

「浏览器通道」每个通道都要写**角色**：需求读取（如日常 Chrome 里的禅道登录态）、执行（默认本地 Playwright 工程）、诊断（CDP 只读，失败步才开）。候选只测两个，其余记 `未验证`；表里每行都要有可执行的验证方式，不许写"应该可用"。**本地 Playwright 工程是执行通道的首选候选**，即使没有对应的 MCP；通道名里写工程路径与版本，验证方式写 `npx playwright --version`、`--list` 或一次 smoke，登录态写 storageState／独立 profile。不要因为浏览器缓存目录为空就判没装（`channel: 'chrome'` 时本来不下载 Chromium）。

**浏览器预检**在步骤 0 做一次：下载目录是否可写；源站是否允许自动/多下载；`chrome://policy` 是否有 `DownloadRestrictions`；宿主是否每次弹"允许自动化浏览器"；PDF/Office 能否查看。预检结果写进表里，影响通道选择和 runbook 的人工介入点。

## discoveries.md（发现台账）

dev-smoke 也要落，但只记"以后会因此改变做法"的条目，一行一个；跑测试与写 runbook 前先读全部标「坑」的条目。流水账、进度、每次观测都不记。

```markdown
| 序号 | 日期 | 产生环节 | 一句话发现或纠正 | 类型（环境事实／需求口径／坑／决策） | 影响哪些 runbook | 状态 |
|------|------|----------|--------------------|---------------------------------|--------------------|------|
| L-001 | 2026-10-21 | R1 步骤4 | 把 toast 当字段校验文案，判据错位 = 假通过 | 坑 | 全部 | 生效 |
| L-002 | 2026-10-21 | R2 步骤b | 列表页数据来自缓存接口，改完不刷新看着没变 | 环境事实 | R2+ | 已提升→environment.md#浏览器通道 E-03 |
```

状态取值：`生效`｜`已提升→目标条目`｜`已推翻→新条目`（被推翻的行与新行都留着，看得出结论怎么变的）。需求外观察先写 close-out 的「需求外观察」行；只有会改变以后做法的，才提升为台账（类型=坑／需求口径）。

## index.md（续接索引）

```markdown
## 索引 — <topic> 测试
- 测试档：<dev-smoke／full> ｜ 本轮轮次：<冒烟／全量> ｜ 执行档：<实探／合段断言／脚本档>
- 执行通道：<环境文档#浏览器通道 E-xx> ｜ 诊断通道：<CDP 只读／trace>
- 执行契约：<execution-contract.md 绝对路径>
- 需求出处：<禅道 URL 或"用户口述"> ｜ 需求快照：<绝对路径> @<日期>
- 环境文档：<绝对路径> ｜ 发现台账：<绝对路径>
- 诊断上限：<根因级／现象级>
- 执行方式：<由用户开新会话执行>／<自检轮：本会话兼任执行，不构成交付验证>
- 并发分组：
| 组 | runbook | 只读/写 | 共享数据键 | 账号 | 并行条件 |
|----|---------|---------|------------|------|----------|
| 串行 | R2、R3 | 写 | 同一记录主键、同一 project 编号 | C-01 | 共享数据，禁止并行 |
- 覆盖对照：
| 条款号 | 一句话要求 | 指向 | 状态 |
|--------|------------|------|------|
| A-01 | 提交后列表出现新记录 | R1#7, R1#8 | ✅实测（证据：results.md#7/#8） |
| A-02 | 手机号非法时拦截 | R1 变体V2 | 本轮未开启（冒烟；开启条件：轮次=全量） |
| A-03 | 页面文案与需求一致 | R1#3 | 代码确认（未实测；原因：本轮无该状态数据） |
- 旅程清单：
| runbook | 终态判据 | 定位三态 | 最近跑过 | 结果 | close-out |
- 未覆盖项与原因：<条款号 + 为什么没覆盖，交谁裁决>
- 待解问题：
```

覆盖对照的左列就是需求快照的条款清单，逐条填，不许有空行；指向格式 `R<n>#<步骤号>`，变体写 `R<n> 变体V<k>`。状态取自最近一次 close-out（细项证据可回指 `results.md`），不另开一份进度表；`本轮未开启` 必须带原因与开启条件。

状态词表只有：`✅实测`（本轮当场观测到）、`代码确认`（只读到代码，未实测）、`观测缺失`、`本轮未开启（原因 + 开启条件）`、`未覆盖（原因 + 裁决人）`、`未跑`。`✅实测` 不能用在只有代码确认或单样本不足的条款上；样本受限时在状态后注 `样本限制：...`。收尾时必须核对：close-out 标了 `代码确认／观测缺失／未实测` 的，index 不得写 `✅实测`；close-out 的缺口必须出现在未覆盖项或待解问题。

**并发分组**是编排会话的排班表：只读 + 无共享数据键 + 独立 context/profile/下载目录的 runbook 才能放同一并行组；写操作或共享数据键的一律串行。执行会话不能自己改分组。

## requirement.md（需求快照）

```markdown
> 需求快照：原文与出处。不改写正文；补记只追加段落并记时间。

## 出处
| 来源类型（需求系统/文本/文件） | URL 或 说明 | 需求编号 | 抓取时间 | 抓取方式 |

## 正文
<dev-smoke：只保留验收相关段落；full：原样落盘，含表格与字段说明，保留原文编号>

## 验收条款
| 编号 | 原文一句话 | 可判定化后的判据（页面/数据上观测到什么） |

## 需求疑点
| 编号 | 疑点 | 处理方式（已问用户／环境文档缺口条目号／假设+复核时点） |

## 增补记录
| 日期 | 补了什么 | 出处 |
```

可判定化只做一件事：把"要好用""应该能查"翻成能观测的事实。翻不出来的进「需求疑点」，不替用户补需求。dev-smoke 的正文只留验收相关段落，不复制整篇需求；full 才全文落盘。

## execution-contract.md（共享执行契约）

每个 topic 只生成一份，从 `references/templates/execution-contract.md` 实例化，落 `YYYY-MM-DD-<topic>/execution-contract.md`。它包含：环境/需求/台账/证据/close-out 的绝对路径、测试档默认值、执行与诊断通道、预算、R1–R10、取证规则。

runbook 头部只写它的绝对路径，**不内联契约正文**；执行会话开工先读它。契约是过程产物（含绝对路径），默认不提交。

## results.md（dev-smoke 通过步证据）

放在 `runbooks/evidence/R<n>-<日期>/results.md`。执行侧版式见 `references/templates/execution-contract.md` R3：通过步一行一步，observed 必须具体（文案、URL、条数、状态、表头数组），不能写"正常"；失败步另开 `snap-R<n>-<步骤号>.md`，视觉项才加 png。纯文字判定不截图。

## close-out（≤1 页机器回程件）

放在 `runbooks/close-out/R<n>-<日期>.md`。执行侧版式见 `references/templates/execution-contract.md` R8：完成度、失败项、诊断补充、数据处置、需求外观察、需回写需求快照、预算使用、证据清单、回程。不重复 runbook 正文，不写用户报告。`无／不确定／blocked` 都是合法值；不许为好看编内容。

## _lib/（脚本原语库）

按 **操作原语 × 模块** 归档，不按需求归档——需求每次变，原语才重复。卡片的字段、probe 与失效判据在 `references/automation-scripts.md`，本文件只定位置：

```
docs/testing/_lib/<module>/<primitive>.md          # 原语卡（说明、锚点、probe、失效判据）
tests/e2e/<module>/<primitive>.spec.ts             # 可执行用例（项目自己的 e2e 目录）
```

卡片名用动词短语（`open-create-task-modal`、`fill-compatibility-matrix`、`read-sample-code-column`），不用需求名。同一原语有多个版本时保留最新一张，旧版在被新卡取代时删除，卡片里记"取代于 <日期>"一句。卡片里记可执行用例的相对路径；**脚本和卡片都放被测项目（或项目指定的独立 e2e 工程），skill 仓库只带格式**。

## 用户可见输出

skill 不生成测试报告、缺陷报告或任何"给用户看"的文档。用户可见结论只在执行会话末尾输出：结果 x/y、失败步、现象 vs 预期、证据路径、数据处置。close-out 是给编排会话的机器回程件，不是用户报告；需要入库由用户自己拍板。
