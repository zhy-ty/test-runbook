# 浏览器取证细则（写「取证」列与跑测试时查）

通道固定：chrome_devtools MCP + CDP 快照，真实 Chrome 默认 profile（登录态在这里）。生成侧按本文件填 runbook 的「取证」列；执行会话靠 runbook 契约 R3 的绝对路径指针读它。

## 一步一条证据

每步至少留一条**能判定该步预期的**证据，命名与 runbook「取证」列一致，存到 runbook 头部记的绝对目录：

- 文案、URL、条数、状态值 → 取 CDP 快照（accessibility/DOM 文本），它才是判据；截图不能替代读到的文字。
- 视觉排版、颜色、图表形状 → `take_screenshot` 存 `snap-R<n>-<步骤号>.png`。
- 下载、导出类 → 证据在文件系统里：记落地绝对路径与大小/行数，页面提示只作辅证。

判定三步：**观测**（读哪个控件的哪段文本）→ **比对**（和「预期」哪一段逐字对）→ **落档**（写到哪个文件/快照）。写 runbook 时就把这三段拆进「观测点」「预期」「取证」三列。

## 别把没等到当成失败

判"没出现"之前，先按该步的预期动作等一次并记下等待时长，再重试同一观测；两次都无才标 ✗。偶发成功走契约 R4a。异步加载、骨架屏、虚拟列表都在制造这种假失败。

## 常见坑（这些形状一眼看不出没生效）

- **页面切换**：新开标签页/窗口后要先 `list_pages` + `select_page`，否则点到了、快照读的还是旧页面。
- **iframe 内的表单**：快照读不到时先确认控件在不在 frame 里，并在该步「动作」列写清先切 frame。
- **对话框**：原生 alert/confirm 要 `handle_dialog`；页面内自绘弹框按普通控件点。
- **虚拟列表**：只渲染可见行。要把某条数据当证据，先加"滚动/筛出让该行进入视口"的步骤，再取快照。
- **校验文案位置**：字段下方红字、toast、按钮禁用态是三种不同观测点，「观测点」列要指名是哪一种。
- **登录态掉线**：被踢回登录页时按环境文档凭据条目重登，并往发现台账追加一行（类型=坑）。
